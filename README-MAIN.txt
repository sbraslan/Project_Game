# Metin2 Game Runtime - FreeBSD 14.x amd64

This repository contains the Metin2 runtime/game files and the server-management automation.
The active automation target is **FreeBSD 14.x amd64 + Python 3 + GCC 14**.

## Required runtime/build tools

Typical FreeBSD packages for the current x64 source branch:

    pkg install python3 gmake gcc14 boost-libs mariadb1011-client devil git

Optional build cache:

    pkg install ccache4

The server source is maintained separately in:

    sbraslan/Project_ServerSRC
    branch: modernization/x64

Keep Project_Game and Project_ServerSRC next to each other when possible. Otherwise set SERVER_SRC explicitly.

Example:

    export SERVER_SRC=/usr/home/Project_ServerSRC

## First setup

From the Project_Game directory:

    chmod u+x admin_panel.sh daemon.sh *.py
    chmod u+x game/share/locale/europe/quest/*.py
    chmod u+x game/share/locale/europe/map/*.sh game/share/locale/europe/map/*.py

Check the x64 environment:

    ./admin_panel.sh 890

Generate/refresh the runtime layout:

    ./admin_panel.sh 666

Build the current 64-bit server source and deploy game/db into game/share/bin:

    ./admin_panel.sh 888

For later incremental development builds:

    ./admin_panel.sh 889

Compile quests:

    ./admin_panel.sh 777

Start the server:

    ./admin_panel.sh 1

Stop the server:

    ./admin_panel.sh 2

## Environment variables

The automation supports these overrides:

    PYTHON_BIN=python3
    SERVER_SRC=/path/to/Project_ServerSRC
    BUILD_JOBS=8
    M2_GAME_DIR=game
    M2_LOCALE=europe
    M2_DAEMON_INTERVAL=10

Generator/network overrides:

    M2_ADMIN_IP=192.168.x.x
    M2_ADMIN_PASSWORD=...
    M2_SQL_HOST=localhost
    M2_SQL_AUTH="metin2 password"

The old values remain fallback defaults in gen_settings.py for compatibility. Prefer environment variables on real servers so credentials do not need to be edited into scripts.

## x64 build/deploy flow

The source Makefiles in Project_ServerSRC build with GCC 14, C++20 and -m64.
admin_panel.sh passes the runtime deploy directory explicitly:

    Project_Game/game/share/bin

After a successful build, the source Makefiles create:

    game/share/bin/game
    game/share/bin/db

gen.py then maintains the per-core runtime links and generates:

    start.list
    clear.list
    ipfw.rules
    game/*/CONFIG
    game/db/conf.txt

Do not manually maintain start.list or clear.list; regenerate them with option 666 after changing gen_settings.py.

## Server management

    ./admin_panel.sh start
    ./admin_panel.sh starti
    ./admin_panel.sh startall

    ./admin_panel.sh stop
    ./admin_panel.sh stopi
    ./admin_panel.sh stopall

    ./admin_panel.sh clear
    ./admin_panel.sh search
    ./admin_panel.sh check

The daemon uses .daemon.pid and periodically calls the Python 3 start controller. It only starts missing processes.

## Backups

The legacy admin panel supports baks/db and baks/fs Makefiles when those directories exist.
This repository currently does not require them to exist; backup menu entries fail safely if they are absent.

## Firewall

ipfw.rules is generated by gen.py. Review it before enabling it on a remote server.
A bad IPFW rule can lock out SSH access.

## Notes

- Python 2.7 is no longer used by the management/generator scripts.
- Core dumps and Python bytecode are ignored by Git.
- start.py and stop.py support CH1, CH2 and CH99 according to the generated start.list.
- The old qc quest compiler is a binary artifact. The Python automation prefers qc_x64 when one is present and otherwise falls back to qc.
